# Delivery insights

`GET /api/v1/insights?repository_id=<uuid>` is a read-only, repository-filtered summary built only from retained, deduplicated webhook deliveries. It returns `send_back`, `first_ci_success`, `cycle_time`, and evidence-linked `suggestions`.

Send-back numerator is a recorded return from `review` to `in_progress`; denominator is recorded submissions from `in_progress` to `review`. Repeated delivery IDs are deduplicated. GitHub `status:*` and GitLab `Status::*` label values are normalized from nested retained issue payloads; merge-request hooks do not become issue transitions. First-run CI groups by pull request and pipeline ID, selects the pipeline with the earliest provider-recorded start time, then uses that pipeline's earliest recorded completion time and conclusion. Only PRs with PR identity, pipeline ID, SHA, conclusion, and provider start/completion timing are eligible; unknown history is omitted rather than inferred from delivery receipt time. This approximates first-run green among represented PRs, not all PRs ever created.

Cycle time starts at the first recorded `in_progress` status and ends at the next recorded `done`. Reopens start a new interval; blocked time remains included; open intervals are excluded. The metric does not use `updated_at` and cannot reconstruct transitions missing from webhook history.

Suggestions require at least two distinct retained delivery IDs with failure conclusions for the same SHA; this is evidence of repeated recorded failures, not proof of a common root cause. They include delivery evidence and never write `FIVE-MINUTES.md`; one-off failures produce no suggestion. `history.complete` remains false: webhook retention has no known backfill boundary, so even nonempty history cannot establish completeness. Metrics describe recorded transitions only. Cycle duration is wall time from the first recorded `in_progress` through `done`, including blocked intervals; re-opened completed work starts a new cycle, unfinished intervals are excluded.
# Insights

`GET /api/v1/insights/delivery?from=YYYY-MM-DD&to=YYYY-MM-DD&repository_id=<uuid>` reports delivery quality for the authenticated organization. Entity counts are persisted merged PRs and closed issues in the date window; `eligible` is the subset with linked runs and known historical prices. Actual cost excludes subscription runs, while equivalent cost uses the price effective at each run's UTC start. Repository identity is part of every key and organization predicates are applied in database queries. Unknown prices and missing linkage are unavailable, never invented zeros. Retained history is explicitly incomplete because no backfill boundary is stored. Existing send-back and first-CI definitions are retained. Issue-to-merge lead time requires a real issue start event and linked merged PR timestamp; issue closure is not a merge proxy. Harness comparison is eligible only when provider additions/deletions are observed; missing diff evidence is unavailable.

`GET /api/v1/insights/analytics?from=YYYY-MM-DD&to=YYYY-MM-DD&period=daily|weekly&group_by=harness|model|wave|area` returns deterministic UTC buckets for authenticated organization data. The inclusive `from` and exclusive next-day `to` range is limited to 366 days; weekly buckets start Monday. Cache hit rate is `cached_input_tokens / (input_tokens + cached_input_tokens)`, and zero denominators return `0`. Prices are selected using the historical model price effective on each run's UTC start date. `actual_cost_usd` excludes subscription runs, while `equivalent_cost_usd` includes them. Missing prices are not fabricated and are counted. Area is read only from exactly one `area:*` label on exactly one issue; missing, multiple, or multi-issue classifications become `unknown`, so a run contributes to totals once and is never double counted.
